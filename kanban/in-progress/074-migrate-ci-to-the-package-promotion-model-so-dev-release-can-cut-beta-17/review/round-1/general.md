## Issues

### Issue 1 — Severity: bug
- File: .github/workflows/workflow.yml:104
- Description: The ubuntu matrix leg uploads `Packages-${{ github.run_number }}` as soon as that leg succeeds (lines 104–112, `if: success() && matrix.os == 'ubuntu-latest' && github.ref == 'refs/heads/master'`). The windows and macos legs can still fail. `packages-prune` waits for every leg (`needs: test` and `if: success()`), so a red run does not delete anything, and locate-run's `--status success` will not promote that run. The artifact remains for `retention-days: 7` and its name starts with `Packages-`. The prune script (lines 131–149) lists every non-expired repo artifact with that prefix, sorts by `created_at`, and deletes all but the two newest. It does not read the workflow run conclusion. Nuru uploads `Packages-*` only from the job that runs after every stage has passed, and it stages the bytes under a name that does not start with `Packages-` because this prefix is the promotable set. After one master run whose ubuntu leg passed and another OS leg failed, the next green run keeps the failed run's artifact as one of the two newest and can delete the previous green run's packages. `dev release` walks back to a green run and then requires a live `Packages-*` artifact. The latest green commit still promotes. The previous green commit, which keep-last-two is there to retain, can be pruned while a failed-run artifact occupies the spare slot. That orphan also counts against the org artifact quota the task cited for not uploading on pull requests.
- Suggestion: Do not publish the `Packages-*` name until every matrix leg has passed. On the ubuntu leg, when `github.ref` is `refs/heads/master`, upload the nupkgs as `staged-packages` (the name must not start with `Packages-`). In `packages-prune`, which already runs only after `needs: test` succeeds, download that artifact, upload `Packages-${{ github.run_number }}` with `if-no-files-found: error` and `retention-days: 7`, run the existing keep-last-two script, then delete `staged-packages`. That is the current Nuru split. Filtering the prune list to artifacts whose workflow run conclusion is `success` also protects the two green slots, and it still leaves `Packages-*` blobs on red runs until the next green prune.
